# 四季報クイズの試作（quiz_prototype）

アプリ本体に「四季報クイズ」を入れる前に、どんな形のクイズがよいかを比べるために作った試作です。
**このフォルダのファイルは、アプリ本体からは使っていません。** 検討の記録として残しています。

## なぜ作ったか

ヘルプ（四季報ミニガイド・指標の見方）は情報が正しくても文章が長く、就活生が最後まで読むのは大変だと考えました。
そこで、同じ情報をクイズにして「どこを見ればいいか」「数字をどう読むか」を覚えられるようにしたいと考えました。

いきなり本体に入れるのではなく、まず形の違うクイズを10パターン作って、実際に解き比べてから決めることにしました。

## 開き方

`quiz_prototypes.html` をブラウザで開くだけで動きます（サーバー不要）。上のタブで10パターンを切り替えられます。

## 10パターン

| | 形 | 身につくこと | 本体に入れたか |
|---|---|---|---|
| A | 欄あて4択 | どの欄に書いてあるか | ✅ |
| B | 就活の悩みから選ぶ | 知りたいこと → 見る指標と欄 | ✅ |
| C | 紙面タップ（欄の図から選ぶ） | 欄の名前と、そこに何があるか | ✅ |
| D | ○✕スピード | 数字の読み違い・落とし穴 | ✅ |
| E | 2社どっち？ | 数字を読んで判断する力 | ✅ |
| F | 計算ドリル | 四季報の数字から指標を出す力 | ✅ |
| G | 見出し判定 | 記者コメントの見出しの意味 | ✅ |
| H | 企業探偵 | 欄を組み合わせて1社を読む流れ | ✅ |
| I | ペア合わせ | 情報と欄の対応を一気に | ― |
| J | 自分診断 | 自分が最初に見るべき数字 | ― |

## 検討して決めたこと

- **答えがある8つ（A〜H）を本体に入れた。** どれも面白く、1つに絞らずに種類を混ぜて出す形にした
- **I（ペア合わせ）は見送った。** Streamlit では「1回目に押したもの」を覚えておく工夫が要り、ボタンも多くて画面の更新が重くなるため
- **J（自分診断）は見送った。** 正解のない形なので、「解いた記録を残して、前回まちがえた問題を出す」仕組みと合わないため
- **C の欄の並びはイメージにした。** 本物の紙面の配置をそのまま再現すると、四季報の紙面のコピーに近くなるため
- **試作を触って出た改善を、本体に反映した**
  - 「次へ」ボタンの位置が問題ごとにばらばらで、スクロールが面倒 → 問題文のすぐ右（スマホでは下）に固定し、解説も同じ場所に出す
  - クイズを切り替えると正解の記録が消える → ログインしたアカウントごとに解いた記録を保存する
  - 毎回同じ問題になる → 問題を増やし（試作は各5〜6問、本体は62問）、まだ解いていない問題・前回まちがえた問題を優先してランダムに出す

## 試作と本体の違い

| | 試作（このフォルダ） | 本体 |
|---|---|---|
| 作り | HTML と JavaScript の1ファイル | Streamlit（`analysis02.py` の `page_quiz`）と `quiz_bank.py` |
| 問題の数 | 各5〜6問 | 8種類・62問 |
| 記録 | 残らない（タブを切り替えるとリセット） | Supabase の `quiz_answers` にアカウントごとに保存（閲覧専用アカウントは保存しない） |
| 出題 | 毎回同じ順番 | 未解答 → 前回まちがえた → 正解済み の順に、ランダム |

## 補足

- 問題と解説の中身は、ヘルプと同じ `shikiho_guide.py` の情報から作った。G の点数は、アプリの見出し辞書の値（生成AIの補助を受けて付けたもの）
- 試作のコードは、生成AI（Claude）に作ってもらった。10パターンを実際に解き比べて、どれを本体に入れるか、どこを直すかを決めた
